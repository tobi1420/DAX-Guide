# Setup Permision between Microsoft Azure and Microsoft Business Central for API Requests.

    # For Business Central Cloud tenants one must create an App Registration in Microsoft Azure. Consult this guide if in doubt: https://yzhums.com/20690/
    # Go to Azure App Registration https://portal.azure.com/#view/Microsoft_AAD_RegisteredApps/ApplicationsListBlade
    # Create a new registration and enter name and set supported account type to single tenant. Suggested naming convention: bc-adp-app

    # Go to Azure Authentication https://portal.azure.com/#view/Microsoft_AAD_RegisteredApps/ApplicationMenuBlade/{ApplicationID}/Authentication/
    # Add a platform of type Web and set the Redirect URI to https://localhost:8080/login
    # Save the Application ID for later use in Postman for Token generation

    # Go to API Permission and add a permision https://portal.azure.com/#view/Microsoft_AAD_RegisteredApps/ApplicationMenuBlade/CallAnAPI
    # Choose Dynamics 365 Business Central and the type Delegated Permision. Mark user_impersonation and Financials.ReadWrtie.All and add the permision
    # Apply the same steps but this time choose Application Permision. Mark app_access, API.ReadWrite.All and Automation.ReadWrite.All and add the permision
    # Grant Admin Consent for the App by clicking next to add permision. Click yes and all permisions are granted for the application

    # Go to Certificates and Secrets https://portal.azure.com/#view/Microsoft_AAD_RegisteredApps/ApplicationMenuBlade/~/Credentials
    # Create new Client Secret with an Description and an Expiration Date of chosen period
    # Save the Client Secrets Value and Secret ID for later use in Postman for Token generation
    # The Secret ID Value will not be shown again after window is closed so please do copy this immediately. 

    # Config in Azure is completed

    # Go to Business Central and search for 'Microsoft Entra Applications'.
    # Create new Application and paste the Application ID in the Client ID Field. Remeber to include the ID in curly brackets {}
    # Set the state to 'Enabled'
    # Assign permision in Business Central for the Application with the permision role of 'D365 BUS PREMIUM', 'D365 FINANCE' and 'D365 FULL ACCESS'
    # Search for 'Microsoft Entra Applications again and ensure that the Application is set to 'Enabled'

    # Config in Business Central is Completed

# Develop Business Central Extensions for specific pages to retrieve data via API Requests in Developer/Sandbox Environment. 

    # For Business Central Extensions one must create an AL Package to expose certain Tables as Endpoints.
    # Download Visual Studio: https://visualstudio.microsoft.com/
    # Navigate to Extensions Pane
    # Install AL Language extension for Microsoft Dynamics 365 Business Central by Microsoft
    # Install AZ AL Dev Tools/AL Code Outline by Andrzej Zwierzchowski

    # Config for Visual Studio is Completed

    # Open a new Window in Visual Studio
    # Press 'F1' on the keyboard and type 'AL: Go!'
    # Choose a path on your computer for the Package
    # Choose newest Business Central release wave and version as Target Platform
    # Tick 'Trust the authors of all files in the parent folder 'AL' and click 'Yes, I trust the authors'    
    # Press 'F1' and type 'Download Symbols' to get all the meta data for the Business Central Tentant
    # In the 'launch.json' file adjust the variables 

      name:                 Microsoft cloud sandbox/production
      environmentType:      Sandbox/Production  
      environmentName:      sandbox/production

    # In the 'app.json' file adjust the variables

      name:                 Name of the extension (Customer API Endpoints)
      publisher:            Company of the publisher (Relesys)
      version:              1.0.0.0 (must always be incremented for Production Per Tenant Extension)
    
      "idRanges": [{"from": 50100, "to": 50149}] - Adjust this to include unused table Ids.

    # Config for AL Extension is Completed

    # Right click in the Explorer Area and choose 'New AL File Wizard (AZ AL Dev Tools)
    # Choose 'Page' in the dropdown 
    # Set Page Type to 'API'

      Object Name:          Name of Object
      Source Table Name:    Choose table from dropdown. All tables are available due to Symbols. 
      API Group:            Set API Pusblisher to Company Name (camelCase)
      API Pusblisher:       Name of the Developer who made the API.
      Entitiy Name:         Name of Object
      EntitySet Name:       Name of Object in Pluralis

    # Pick only the necessary fields and flow fields from the field overview to enhance performance.

    # In the actual AL File set the variable Editable = false;

    # Press 'F5' on keyboard to build an AL package and hereafter deploy this to the Sandbox Environment
    # Assign permision in Business Central for the Application with the permision role of 'D365 BUS PREMIUM', 'D365 FINANCE' and 'D365 FULL ACCESS'
    # Search for 'Microsoft Entra Applications again and ensure that the Application is set to 'Enabled'

# Develop Business Central Extensions for specific pages to retrieve data via API Requests in Production Environment.
    # Since production works with PTE (Per Tenant Extensions) one must manually upload, uninstall and install AL Package for each deploy.
    # Assuming a Development Extension is made proceed with the following steps:
    # Go to Production Environment
    # Search for 'Extension Management'
    # Click on 'Manage' on the Page Ribbon
    # Click 'Upload Extension'
    # In AL Package within Visual Studio type 'F1' and write 'AL: Package' to prepare the extension for upload. 
    # In Business Central upload .app file from the Root folder of the package - Default Publisher_ProjectName_1.0.0.0.app
    # Tick 'By Deploying this extension...'
    # Press Deploy
    # Too see installation stauts go to Manage from the ribbon and click 'Installation Status'
    # When Production must be updated one must uninstall and unpublish the extension by clicking Uninstal and herafter Unpublish. 
      Then the version number must be incremented from the AL Package and then re-uploaded.
    # Assign permision in Business Central for the Application with the permision role of 'D365 BUS PREMIUM', 'D365 FINANCE' and 'D365 FULL ACCESS'
      In the Microsoft Entra Application Page.

# Test and configure OAuth2 Authentication for Business Central API. 
    # Go to Postman and test the following endpoint for companies in a given tenant: https://www.postman.com/downloads/
    # https://api.businesscentral.dynamics.com/v2.0/{TENANTID}/sandbox/api/v2.0/companies. 
      The structure of the link will be analyzed later in this guide (The Tenant ID can be found in the URL of the Business Central Instance)
      https://businesscentral.dynamics.com/{xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx}
    # Of Course an error will occur since the call can not be authorized.

    # Go to the tab Authorization and choose 'Oauth 2.0' 
    # Choose Add Authentication Data to Request Headers
    # In the Request Header View Choose 'Client Credentials' 

    # Set the Access Token URL to https://login.microsoftonline.com/{TENANTID}/oauth2/v2.0/token. Tenant ID can be found in the URL to your Business Central.
    # Set the Client ID to the Application ID saved earlier (App Registration Overview)
    # Set the Client Secret ID to the Client Secret Value saved earlier (This can not be accesed after creation. Please keep it secret, keep it safe)
    # Set the Scope to https://api.businesscentral.dynamics.com/.default
    # Set the Client Authentication to 'Send Client Credentials in Body'
    # Click on 'Get New Access Token' and copy the generated token
    # Click on 'Use this token'
    # Set the header prefix to 'Bearer'

    # Structure of the Business Central API Endpoint for Generic Microsoft Requests
    # https://api.businesscentral.dynamics.com/v2.0/{Tenant ID}/sandbox/api/v2.0/companies

    api :                                                     Indicate that the https request will be aimed towards an api
    businesscentral.dynamics.com :                            Base url for the api
    v2.0 :                                                    Api version to be used
    {Tenant ID} :                                             Tenant id
    sandbox :                                                 Environment
    api :                                                     Api type
    v2.0 :                                                    Api publisher
    companies :                                               Entityname (typically table name)

    # Structure of the Central API Endpoint for Custom API's with custom API Group and API Publisher to retrieve All Companies on Tenant
    # https://api.businesscentral.dynamics.com/v2.0/{Tenant ID}/sandbox/api/{APIPublisher}/APIGroup/v1.0/companies
    # Remember, not all entitites can be called out of the box. One must develop Custom API's in AL and remember to set Editable to False in entity config

    api :                                                     Indicate that the https request will be aimed towards an api
    businesscentral.dynamics.com :                            Base url for the api
    v2.0 :                                                    Api version to be used
    {Tenant ID} :                                             Tenant id
    sandbox :                                                 Environment
    api :                                                     Api type
    APIPublisher :                                            Api publisher (Specific Developer)
    tLDev :                                                   Api group (Typically Company Name)
    v1.0 :                                                    Api version
    companies :                                               Entityname (Typically Table name)

    # Structure of the Central API Endpoint for Custom API's with custom API Group and API Publisher to retrieve All records for a given table for one Company
    # https://api.businesscentral.dynamics.com/v2.0/{Tenant ID}/sandbox/api/{APIPublisher}/{APIGroup}/v1.0/companies({Company ID})/{Entitiy Name}
    # Remember, not all entitites can be called out of the box. One must develop Custom API's in AL and remember to set Editable to False in entity config

    api :                                                     Indicate that the https request will be aimed towards an api
    businesscentral.dynamics.com :                            Base url for the api
    v2.0 :                                                    Api version to be used
    {Tenant ID} :                                             Tenant id
    sandbox :                                                 Environment
    api :                                                     Api type
    {APIPublisher} :                                          Api publisher (Specific Developer)
    {APIGroup} :                                              Api group (Typically Company Name)
    v1.0 :                                                    Api version
    {Company ID} :                                            Company id Retrieved from /api/{APIPublisher}/APIGroup/v1.0/companies
    {Entitiy Name} :                                          Name of API Endpoint (Typically Table Name)

# Setup all necessary Resources for a given Resource Group in Microsoft Azure 
    # Azure Data Factory
        # In Azure go to Resource Groups
        # Click 'Create' to create a new Resource
        # Search for 'Data Factory'
        # Choose Azure Subscription
        # Choose Resource Group 
        # Choose a name for the Data Factory - naming convention (company-environment-adf)
        # Tick 'Configure Git later'
        # Tick Off 'Enable Managed Vitural Network on the default...'
        # Tick 'Public Endpoint' for Connect Via.
        # Tick Off 'Enable encryption using a Customer Managed Key'
        # Optional to set Tags for billing overview

        # Go to the Azure Data Factory Overview
        # Go to Acces Control (IAM) and ensure that the user whom created the Data Factory is set to Owner.
    
    # Config of resource Azure Data Factory is Completed

    # Azure Key Vault
        # In Azure go to Resource Groups
        # Click 'Create' to create a new Resource
        # Search for 'Key Vault'
        # Choose Azure Subscription
        # Choose Resource Group 
        # Choose a name for the Key Vault - naming convention ({company}-{environment}-kv)
        # Choose Region for Instance (Sweden)
        # Choose 'Standard' for Pricing Tier
        # Choose 90 days for 'Days to retain deleted vaults'
        # Tick Disable purge protection (allow key vault and objects to be purged during retention period) for Purge Protection
        # Tick 'Azure role-based access control (recommended)' for Permission model
        # Tick 'All networks' for Allow access from:
        # Optional to set Tags for billing overview
        
        # Go to the Azure Key Vault Overview
        # Go to Acces Control (IAM) 
        # Click 'Add role assignment'
        # Choose 'Key Vault Administrator'
        # Go to 'Members' in Ribbon 
        # Choose 'User, group, or service principal' for Assign access to
        # Click on 'Select members' and choose Entra ID
        # Review and assign the Role

        # Go to the Azure Key Vault Overview
        # Go to Acces Control (IAM) 
        # Click 'Add role assignment'
        # Choose 'Key Vault Reader'
        # Go to 'Members' in Ribbon 
        # Choose 'User, group, or service principal' for Assign access to
        # Click on 'Select members' and choose Entra ID
        # Review and assign the Role

        # Go to the Azure Key Vault Overview
        # Go to Acces Control (IAM) 
        # Click 'Add role assignment'
        # Choose 'Key Vault Secrets User'

        # Choose 'Managed Identity' for Assign access to
        # Click on 'Select members' and choose Entra ID
        # Choose Azure Subscription
        # Choose 'Data Factory (V2)' as Managed Identity
        # Click on 'Azure Data Factory Resource'
        # Review and assign the Role
